# 语音输入采用按需本地转写与实测闸门

QuickNote MVP 默认提供本地转写，云转写实现延后；共享核心只保留平台中立的转写后端接口、状态和错误分类，不交付云端设置、凭据或网络调用。单次语音输入最长 60 秒且绝不持续监听。录音片段只在当前操作和有限重试期间存在，正常结果插入录音结束时冻结的光标位置，可疑结果先进入转写预览。

应用本体只包含录音、调度和稳定接口；语音模型及推理运行时组成用户明确确认后才下载的版本化本地转写包，与主安装器和应用本体分别计量。本地推理在按需 sidecar 中执行，完成后退出；不用语音时不得存在推理进程或加载模型。模型下载、更新、修复和删除都必须显式可见，更新完成并自检成功后原子切换版本。

默认模型必须通过同语料 Windows 实测才能确定。验证任务比较 SenseVoice-Small INT8 + sherpa-onnx 与 whisper.cpp `base-q5_1`：至少 100 条、最长 60 秒的中文样本，在 4 核、8 GiB、CPU-only 的 Windows 11 x64 基线机上达到人工“一次可用率”至少 90%，并满足 5、30、60 秒片段热转写 P95 分别不超过 800 ms、2 s、4 s。许可、编辑响应性、零音频网络请求、临时音频清理和 sidecar 退出后的资源回落均是硬门槛。

只有一项合格时选择该项；两项都合格时优先采用配对样本证明质量更好的方案，质量没有可信差异时依次比较压缩下载体积、峰值内存和冷加载时间。两项都失败时不静默改用云端，而是把语音移出本次发布并重新审议 MVP 边界。本地 sidecar 崩溃或超时只自动重试一次，确定性错误不自动重试，录音片段也不跨应用重启保存。

本决策以本地优先、无需登录和可控隐私换取较大的按需下载与本地推理成本。未来交付云转写前，必须另行决定供应商、凭据管理、费用、处理区域、数据保留和显式降级规则。
