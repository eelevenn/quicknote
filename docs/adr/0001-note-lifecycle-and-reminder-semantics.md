# 便签生命周期与提醒采用单向收敛模型

QuickNote 将已持久化便签限制在 `活跃 ⇄ 归档 → 回收站 → 永久清除` 的生命周期中，当前便签只指向活跃便签，空白草稿在首次保存非空白正文前没有身份。这个约束牺牲了从活跃状态直接删除和一步恢复到活跃状态的便利，换取删除意图、当前便签继任和崩溃恢复均只有一种解释。

归档会永久清除提醒，但保留截止时间；每张活跃便签至多有一个提醒。系统只在到点时尝试通知且不补发；通知提供“打开”和“稍后提醒”，稍后提醒把同一个提醒从动作发生时延后一个固定的用户首选时长，不创建并列提醒或周期规则。未收到打开或稍后提醒动作的到期提醒表现为便签上的“错过提醒”，由用户主动打开便签响应。这样既不把 Windows 无法可靠报告的通知消失事件当成领域事实，也保留了低成本延后当前提醒的能力。

只有显示“已自动保存”的版本承诺可以在崩溃后恢复。任何会离开当前编辑上下文或改变生命周期的操作，都必须先完成待保存内容；保存失败时操作不得生效。
