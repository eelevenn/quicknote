# 便签生命周期与提醒采用单向收敛模型

QuickNote 将已持久化便签限制在 `活跃 ⇄ 归档 → 回收站 → 永久清除` 的生命周期中，当前便签只指向活跃便签，空白草稿在首次保存非空白正文前没有身份。这个约束牺牲了从活跃状态直接删除和一步恢复到活跃状态的便利，换取删除意图、当前便签继任和崩溃恢复均只有一种解释。

归档会永久清除提醒，但保留截止时间；提醒是每张活跃便签至多一个的一次性安排。系统只在到点时尝试通知，不补发、不提供推迟操作；未响应的到期提醒改为便签上的“错过提醒”，由用户主动打开便签响应。这样避免把无法确认的 Windows 通知显示结果当成领域事实，也不需要维护提醒重试或稍后提醒链。

只有显示“已自动保存”的版本承诺可以在崩溃后恢复。任何会离开当前编辑上下文或改变生命周期的操作，都必须先完成待保存内容；保存失败时操作不得生效。
