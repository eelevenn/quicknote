# 采用 SQLite 单写者存储与版本化导出

QuickNote 使用一个位于平台本地应用数据目录的 SQLite 数据库作为便签、当前便签、截止时间、提醒与内部调度意图的唯一事实源。共享 Rust 核心通过单一后台存储线程串行执行命令，Windows 或未来移动平台只能在数据库事务提交后投影系统提醒；这使跨便签的当前指针、生命周期变化和提醒幂等性能够保持原子，而无需用多个正文文件协调全局状态。

数据库使用 bundled SQLite、WAL 与 `synchronous=NORMAL`。自动保存采用 250 ms 尾随防抖和 1 秒最大等待时间，只有最新修订提交成功后才显示“已自动保存”；该反馈承诺抵抗应用进程崩溃，但不承诺系统崩溃或突然断电时零数据损失。切换便签、关闭编辑上下文、归档和导出必须先提交最新内容，失败时原操作不生效。

当前便签由零或一行的 `current_note` 关系表示，不使用宽泛的应用状态表或便签上的 `is_current` 标志。提醒状态与持久 outbox 在同一事务变化，平台调度失败通过退避和启动/恢复协调重试。Schema 使用稳定 UUID、UTC Unix 毫秒和前向迁移；新版本数据库拒绝被旧客户端写入。

自动备份通过 SQLite Online Backup API 生成一致快照，并在每日首次写入和迁移前运行。损坏恢复永不静默覆盖原文件，而是隔离故障数据库并由用户选择已验证备份进行整库恢复。完整 JSON 是版本化、无损且面向未来导入的数据契约；单张 Markdown 是带 YAML front matter 的人类可读导出。两者都排除 outbox、动作收据和平台调度标识等可重建运行状态。

这个选择不支持 MVP 数据目录迁移、应用级加密、云同步、记录级备份合并或 schema 降级。自动备份最多保留 30 天，永久清除便签时会重置可能仍含该便签的备份历史；用户自行保存的 JSON 和 Markdown 不受应用控制。
